What is the Internet of Things?

Start with the basic idea of IoT before interacting with the robotic arm.

Lesson 1: Understanding IoT

The Internet of Things, or IoT, is a way for physical devices to collect information, process it, communicate, and perform an action. A simple IoT system usually has an input, a controller, a method of communication, and an output.

Learning objective

After this lesson, you should be able to explain how a physical event can become digital data and then cause a physical response.

The four basic parts

1. Input / SensorDetects something in the real world, such as color.
2. ControllerProcesses the sensor reading and decides what to do.
3. CommunicationAllows software and devices to exchange commands or data.
4. OutputPerforms an action, such as moving a servo motor.
IoTrack exampleA website command can request an activity from the robot.
Why it mattersIoT connects software with events and actions in the physical world.
Example:

Imagine a smart light. A sensor notices the room is dark, the controller processes that information, and the light turns on. IoTrack demonstrates the same input → processing → output idea using a robot.

MODULE 2 · LESSON

Robotic Arm Movement and Manual Control

Learn how individual commands correspond to physical movements, then control the arm manually.

Lesson 2: Controlling Servo-Based Movement

A robotic arm uses servo motors at its joints. Each servo can move to a programmed position or angle. Instead of running an entire automatic sorting routine, software can also send individual movement commands.

Learning objective

Explain how a software command can be translated into a specific movement of the robotic arm.

Example commands

LEFT / RIGHTRotates the base to change horizontal direction.
UP / DOWNChanges the arm's vertical position.
GRAB / RELEASECloses or opens the gripper.

Automatic vs. manual control

  • Automatic: one command starts a complete programmed sequence.
  • Manual: the student sends one movement command at a time.
  • Home: returns the robot to its known starting position.
  • Stop: immediately stops the activity.
Example:

Pressing RIGHT on the website can send a MOVE_RIGHT command. The microcontroller receives the command and changes the appropriate servo position.

MODULE 3 · LESSON

Sensors, Data, and Microcontrollers

Learn what a sensor reading means and how the controller uses that information.

Lesson 3: From Physical Event to Data

A sensor does not “think” like a person. It measures physical properties and produces values. The microcontroller reads those values and uses programmed rules to interpret them.

Learning objective

Describe the difference between data collection and data processing.

What happens step by step?

1. Object is placed
2. Sensor measures
3. Controller reads values
4. Program decides

Sensor vs. microcontroller

  • Sensor: gathers raw information.
  • Microcontroller: reads the information and follows programmed logic.
  • Servo motor: carries out a movement requested by the controller.
Example:

If the color sensor produces values that match the programmed range for red, the controller can label the block as RED and choose a sorting action.

MODULE 4 · LESSON

Color Detection

Learn how the color sensor identifies red, blue, and green blocks, then ask the robotic arm to pick up a specific color.

Lesson 4: Detecting a Block by Color

The color sensor gathers red, green, and blue light values from a block. The microcontroller compares those readings with programmed color ranges so the system can identify the block as RED, BLUE, or GREEN.

Learning objective

Explain how a color sensor and microcontroller work together to identify a target block before the robotic arm picks it up.

How the activity works

1. Student selects a color
2. Website sends the command
3. Sensor searches for the target
4. Robot picks up the block

Example

If the student presses Pick Up Red, the website sends PICK_RED. The robot looks for a red block, confirms the detected color, moves to the block, closes the gripper, and lifts it.

Why use separate buttons?

Each button demonstrates that the website can request a specific physical task while the sensor still verifies the color of the block before pickup.

MODULE 5 · OPTIONAL LESSON

Stacking Blocks

Explore how the robotic arm can place one block on top of another while maintaining a stable stack.

Lesson 5: Stacking and Balance

Stacking requires more precision than simply picking up a block. The robot must place each block close to the center of the block below it so the stack does not fall.

Learning objective

Describe why block size, placement, and balance are important when a robotic arm performs a stacking task.

Optional lesson: If the prototype only uses blocks of the same size and reliable stacking cannot be achieved, this lesson can be removed from the final system rather than demonstrating an activity that frequently fails.

Recommended block setup

  • Use blocks with different sizes when possible.
  • Place the largest block at the bottom.
  • Place smaller blocks above the larger base.
  • The robot should release each block near the center of the block below it.
  • If only same-size blocks are available and the stack is unstable, remove or disable this activity.
Example:

Large block → medium block → small block. A wider base gives the upper blocks more support and reduces the chance of the stack falling.

MODULE 6 · LESSON

Pick Up Blocks

Learn how one website command can request a task with a specific number of blocks.

Lesson 6: Repeating a Robotic Task

A robotic routine can be repeated a specific number of times. Instead of manually pressing the pickup control for every block, the student can choose how many blocks should be handled and let the programmed routine complete the requested count.

Learning objective

Explain how a command can include a quantity and cause the robot to repeat a programmed pickup routine.

How the commands work

PICK_1_BLOCKRuns the pickup routine once.
PICK_2_BLOCKSRuns the pickup routine for two blocks.
PICK_3_BLOCKSRuns the pickup routine for three blocks.
Example:

If the student selects Pick Up 3 Blocks, the website sends the requested quantity. The robot then performs the programmed pickup sequence until three blocks have been handled.
